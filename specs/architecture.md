# Architecture: `wk`

## Project Structure

```
worktree_tui/
├── pyproject.toml
├── src/
│   └── wk/
│       ├── __init__.py
│       ├── cli.py              # Entry point, argument parsing, shell wrapper check
│       ├── config.py           # Config file loading (.config/wk.yml)
│       ├── worktree.py         # Data models and wt command interface
│       ├── shell.py            # Shell wrapper generation, detection, command output
│       ├── tui/
│       │   ├── __init__.py
│       │   ├── app.py          # Textual App subclass
│       │   ├── worktree_list.py # Main worktree list widget
│       │   └── theme.py        # Colors and styling
│       └── actions.py          # Shared logic for launch/jump/restart/new/delete
```

## Components

### `cli.py` — Entry Point

The `[project.scripts]` entry point in `pyproject.toml`.

```python
def main():
```

Responsibilities:
- Parse CLI arguments (using `argparse` or just `sys.argv` — lightweight, no framework needed)
- Route to the correct action:
  - `wk` (no args) → check wrapper → launch TUI
  - `wk init zsh` → print shell function, exit
  - `wk new <name>` → check wrapper → create + launch worktree
  - `wk <name>` → check wrapper → launch existing worktree
- On non-wrapped invocations (except `wk init`), run the setup/install flow

### `shell.py` — Shell Wrapper Layer

```python
def is_wrapped() -> bool:
    """Check if running inside the shell wrapper (__WK_WRAPPED=1)."""

def generate_wrapper_zsh() -> str:
    """Return the zsh wrapper function definition string."""

def print_shell_commands(commands: list[str]) -> None:
    """Print shell commands to stdout for the wrapper to eval."""

def run_setup_flow() -> None:
    """Interactive: detect shell, offer to install wrapper, write to .zshrc."""
```

The wrapper function generated by `generate_wrapper_zsh()`:
- Exports `__WK_WRAPPED=1`
- Runs the real `wk` binary, capturing stdout
- Evals the captured stdout (so `cd` runs in the parent shell)
- Passes stderr through (for error messages and Textual's alternate screen)

Important: Textual renders to **stdout** by default. We need to configure it to render to **stderr** instead (via `Textual()`'s `file` parameter or `TEXTUAL_CONSOLE` redirect), so stdout stays clean for shell command output.

### `config.py` — Configuration

```python
@dataclass
class WkConfig:
    open_workspace_cmd: str | None = None
    restart_workspace_cmd: str | None = None

def load_config() -> WkConfig:
    """Load .config/wk.yml from the git repo root. Returns defaults if missing."""

def find_repo_root() -> Path:
    """Find the git repo root via `git rev-parse --show-toplevel`."""
```

Uses `pyyaml` for YAML parsing.

### `worktree.py` — Worktree Data & Commands

```python
@dataclass
class Worktree:
    name: str
    path: Path
    branch: str
    created: datetime

def list_worktrees() -> list[Worktree]:
    """Run `wt list --format json`, parse, return sorted by created date desc."""

def create_worktree(name: str) -> Worktree:
    """Run `wt switch --create <name> --base=@`. Return new worktree."""

def remove_worktree(name: str) -> None:
    """Run `wt remove <name>`."""

def find_worktree(name: str) -> Worktree | None:
    """Find a worktree by name from the list."""
```

All `wt`/`git` commands run via `subprocess.run()` with error handling.

### `actions.py` — Shared Business Logic

```python
def action_launch(worktree: Worktree, config: WkConfig) -> list[str]:
    """Return shell commands to cd into worktree and run OPEN_WORKSPACE_CMD."""

def action_jump(worktree: Worktree) -> list[str]:
    """Return shell commands to cd into worktree."""

def action_restart(worktree: Worktree, config: WkConfig) -> list[str]:
    """Return shell commands to cd into worktree and run RESTART_WORKSPACE_CMD."""

def action_new(name: str, config: WkConfig) -> list[str]:
    """Create worktree off current branch, return launch commands."""

def action_delete(name: str) -> None:
    """Remove worktree. No shell commands returned (stays in TUI or exits)."""
```

Each action returns a `list[str]` of shell commands that `shell.print_shell_commands()` writes to stdout.

### `tui/app.py` — Textual Application

```python
class WkApp(textual.app.App):
    """Main TUI application."""

    BINDINGS = [
        Binding("q", "quit"),
        Binding("escape", "quit"),
        Binding("enter", "select"),
        Binding("j", "jump"),
        Binding("r", "restart"),
        Binding("d", "delete"),
        Binding("n", "new"),
    ]
```

Responsibilities:
- Mount the `WorktreeList` widget
- Handle keybindings and route to actions
- On launch/jump/restart: set a result (the shell commands), exit the app
- On delete: show confirmation, run delete, refresh list
- On new: show input prompt, run create, then launch

**Critical**: The app must write to **stderr** (not stdout) so the shell wrapper can capture stdout for commands only. Textual supports this via the `App(file=sys.stderr)` parameter.

The app returns an "exit result" — either a list of shell commands or `None`. The caller (`cli.py`) uses this to print commands to stdout after the app exits.

### `tui/worktree_list.py` — List Widget

```python
class WorktreeList(textual.widgets.ListView):
    """Navigable list of worktrees with a 'New Worktree' entry at top."""
```

Each list item shows:
- Worktree name/branch
- Created date (relative, e.g. "2 days ago")
- Possibly path or other metadata

The "New Worktree" row is visually distinct (e.g. different color, `+` prefix).

Default cursor position: index 1 (second item — most recent worktree).

### `tui/theme.py` — Styling

Centralized color palette and CSS for the Textual app. Polished look with:
- Color-coded items
- Highlighted selection
- Footer bar showing available keyboard shortcuts

## Entry Point Configuration

In `pyproject.toml`:

```toml
[project.scripts]
wk = "wk.cli:main"
```

Package source lives in `src/wk/` using the `src` layout:

```toml
[tool.setuptools.packages.find]
where = ["src"]
```

Or with uv/hatch, configure the build backend accordingly.

## Data Flow

```
User types `wk` in terminal
        │
        ▼
Shell wrapper function (zsh)
  - sets __WK_WRAPPED=1
  - runs: output=$(command wk "$@" 2>&1 >/dev/null ... )
  - actually: captures stdout, passes stderr to terminal
        │
        ▼
cli.main()
  - checks __WK_WRAPPED
  - parses args
  - routes to TUI or CLI action
        │
        ▼
TUI (renders on stderr)    ──or──    CLI action
  - user interacts                    - runs wt commands
  - selects action                    - returns shell cmds
  - returns shell cmds
        │
        ▼
cli.main() prints shell commands to stdout
        │
        ▼
Shell wrapper evals stdout
  - cd /path/to/worktree
  - .config/wt/start.sh
```

## Error Handling

- **`wt` not installed**: detect at startup, show clear error message with install instructions.
- **Config missing**: proceed with defaults (`open_workspace_cmd = None`). Launch action just does `cd`.
- **`wt` command failures**: capture stderr, display in TUI or print to stderr in CLI mode.
- **No worktrees**: show list with only the "New Worktree" option.
